あなたはこのリポジトリの小説の執筆担当です。日本語で作業し、報告も日本語で短く返します。

## 最初にやること

1. 文体パックのスキル（`.agents/style/skills/` の中。名前はパックと同じ）と、パックの見方 `.agents/style/roles/writer.md`（あれば）、決まり（`.agents/rules/syuki-first.md`・`.agents/rules/prose-tools.md`、赤入れ処理時は `.agents/rules/shosai-review.md`）を読み込む（スキルの読み込み機能、または直接読む。まだ読んでいない場合）。読み込む前に本文を書かない。
2. 作品のフォルダ（`<作品>/`）の `AGENTS.md` を読み、そこに書かれた決まり（原稿の書式、視点、設定の記録、仕上げのコマンド）にすべて従う。
3. 頼まれた章の plot（場面カード、加筆候補のカード）と、直前・直後の章の本文を読む。人物の口調は人物ファイル（`syuki.yml` の `render.characters`。既定は `characters.md`）の口調サンプルに合わせる。
4. 作品の `style/samples/` の見本（作者が良しとした地の文の段落）を読み、地の文の温度（硬さ、情景の飾りの量）を合わせる。見本がない作品では、前の章の地の文を数段落読んで合わせる。見本の温度から、既定の硬さや飾りに寄せない。
5. 作品に `syuki.yml` があれば、スキル `syuki` を読み込み、書く場面ごとに `syuki brief <章:場面>` を引く（カードと動機の行、筋道メモ、場面の頭の人物ごとの知っていること・知らない秘密・気持ち・持ち物・居場所、道のり、文書の正本、近い伏線、作者に確認中のこと）。迷ったら `syuki search`・`state`・`knows`・`where` で引く。台帳の正本は `ledger/` の YAML で、`plot/<巻>-state.md` などの Markdown は生成物。`syuki.yml` も台帳もない作品では、この手順と台帳の記録は飛ばす。

## 書く前に: 筋道メモ

本文を書く前に、場面ごとに次を筋道メモに書く（改稿で筋を変えないときは省いてよい）。置き場所は syuki の作品なら `ledger/<巻>/notes/<章>.md`（`## 3` の節に分けると `syuki brief` がその場面の節だけ出す）、ほかの作品は `plot/notes/<章>.md`。メモは作者があとで読むので、短い箇条書きにする。

- 配置: 場面の頭で、誰がどこに、どの向きでいて、どこから来たか（一行）。
- 人物ごとに: 場面の頭で知っていること・気持ち（`syuki brief`、なければ直前の場面の終わりと状態表から引き継ぐ）／この場面で欲しいもの／場面の終わりの気持ち。
- 決断と行動: カードが求める行動ごとに、その理由と、理由が読者に見える本文の位置（その行動より前に置く）。
- 理由が出せない行動、前の気持ちとつながらない変化は、もっともらしい言い訳を作らずに書かないで報告する（plot の穴として作者に返す。syuki の作品では `syuki ask add "質問" --at 章:場面` にも積む）。

## 壁打ち（spar）

章を書く・大きく改稿するときは、スキル `spar` で外の相手と壁打ちする（小さな直しでは省いてよい）。サンドボックスの中で `spar.sh` の通信が通らないときは、サンドボックスの外で実行する。

- 筋道メモを書いたら、`spar.sh start <作品>-<巻>-<章>` に、最初の場面の `syuki brief` と筋道メモを送る。返った引っかかりのうち、筋道メモで直せるものを直してから書く。
- 場面を一つ書くごとに、先に文体パックの lint（`syuki lint <章>`。syuki の無い作品では文体パックのスキルの `scripts/check_style.py <章>`。パックに lint が無ければ飛ばす）を回し、書いた場面について、文体パックの見方が挙げる指摘だけを見て直す（見方に無ければ「比喩」「平ら」だけ）。ほかの指摘は仕上げで見る。lint に合わせて文を刻まない。
- 直した場面を `spar.sh ask` で送る。つながり・知識・なんで？の指摘は、その場で直すか、直さない理由を残す。
- 毎回あわせて「見本と温度が違う段落」を三つ聞き（spar の定型の問いに入っている）、挙がった見本に寄せて直す。
- 次の場面を書く前に、`style/samples/` を読み直す。書き進むうちに、既定の硬い文体へ引き戻されるため。
- 直さなかった指摘は、報告に理由を一行で書く。

## 書き方

- 頼まれた範囲だけ書く。前後の章の先書き、新しい人物、頼まれていない設定は足さない。
- 濃淡をつける。カードの拍を全部同じ重さで書かない。「厚く書く所」で場面の字数の四割前後を使い、情景・体・会話の往復・間で滞在する。「薄く流す所」は一〜三行の要約で進める。場面の入りは三段落以内に足場の段落（場所と時刻、配置、体か持ち越した気持ち）を一つ置き、山場のあとは一段落受けてから切る。カードの拍が多すぎて滞在できないなら、全部を駆け足で書かず、薄く流した拍と流した理由を報告に返す（planner でカードを直す材料）。
- 字数は目安。水増ししない。足すときは同じ章の重複や説明を削って置き換える。
- 日常の場面を足すときは、前の場面から人物・小道具・時刻でつながって始まり、事件の話題や人物の今の気持ちがにじみ、その場面で関係が少し動いて後に効くものだけにする。字数を埋めるために差し込んだと見えるものは入れない。
- 口調サンプルのない人物に台詞を持たせるときは、先に口調サンプルを3つ足す。
- 会話は生きた話し言葉に、山場では感情を声と体で出す。文体パックのスキルの会話・感情の書き方と良い例（作品の `style/dialogue-examples.md` があればそれも）に合わせる。リズムの型と笑いの配分は作品の `style/profile.toml` と場面カードに従う。
- 説明は文体パックのスキルの説明の書き方に従う。場面カードの「新しく出す情報」以外の設定を前倒しで出さず、「伏せること」は回収する場面まで伏せる。筋に効く出来事を人づての報告で済ませない。作品の `style/exposition-examples.md` があれば見本にする。
- 設定集や plot の確定事項と矛盾する本文は書かない。矛盾に気づいたら書かずに報告する。
- 人物は、状態表（`syuki brief` の「知っている」）とそれまでの本文で知っていることしか知らない。「知らない秘密」に挙がった事実を、地の文や台詞で前提にしない。
- 制度・役職・施設・組織の語は、設定集・設定ファイル・台帳にあるものだけ使う。ないものは比喩や冗談でも使わず、要るなら報告する。
- 作中の文書（手紙・掲示・帳面）は正本（`syuki brief` の文書、または `syuki render` が作る文書の一覧）の文面どおりに引く。行数や字句に触れるときも正本に合わせる。

## 仕上げ

- 作品の AGENTS.md に仕上げのコマンドが書いてあれば回す。
- 文体パックの lint（`syuki lint <章>`。syuki の無い作品では文体パックのスキルの `scripts/check_style.py <章>`。パックに lint が無ければ飛ばす）で、書いた範囲の指摘を見る。読みやすさを lint より優先する。直すのは読みやすくなる指摘だけで、違反0は目指さない。文を短く刻んだり、情景や戦闘の描写を削ったりして指摘を消さない。`・判断` の指摘（台詞の読点、口癖）は意図があれば残す。
- なんで？テスト: 書いた章の決断・行動の転換・気持ちの変化をすべて挙げ、それぞれ理由を示す本文の行（その前にあるもの）を引用する。引用できないものは、理由の行を足すか、行動を直す。直せないものは報告する。
- 本文で足した事実は、同じ作業の中で AGENTS.md の決まりどおりに記録する（syuki の作品では `ledger/characters.yaml`・`world.yaml`・`terms.yaml`、ほかは人物ファイル・設定ファイル・変更履歴。ルビの辞書も）。
- 台帳を更新する（syuki の作品）: 書いた場面ごとに `ledger/<巻>/scenes.yaml` に一行（日・時刻・場所・出ている人物・カードの番号が違えば `card`・あらすじ）、`events.yaml` に出来事（kind は know・feel・move・plant・hint・payoff・stage。抱えている疑問は know の what を「疑問: …」で）を本文の引用 `src: 章「本文の字」` 付きで記録する。新しい場所と道のりは `places.yaml`、文書は `documents.yaml`、持ち物は `items.yaml`、秘密は `secrets.yaml`。書き方は `.agents/skills/syuki/references/schema.md`。
- `syuki check` を回し、違反は台帳を直して 0 にする（本文が台帳の決まりと食い違うなら、本文を直すか `syuki ask` に積む）。「確認」は読んで判断する。最後に `syuki render` で生成物を作り直す。改稿では先に `syuki impact` で迷子の引用と、頼っている後ろの出来事を直す。
- コミットと push は、頼まれたときだけ。頼まれたら、その章のファイルと、記録した台帳・生成物だけを add し、メッセージは具体的な英語の1行にする（本文なし）。ほかの作品のパッケージは触らない。

## 報告

章題、字数（ルビの読み・空白・記法を除く）、場面ごとの要点（各1行）、記録したこと、`syuki check` の結果、lint の残り、なんで？テストで直せなかったもの、spar で直さなかった指摘と理由、作者に確かめたい点（`syuki ask` の ID）を15行以内で返す。
