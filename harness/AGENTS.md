# 【リポジトリの名前】

小説の原稿のリポジトリ。作品ごとにフォルダ（以下「作品のフォルダ」、例 `mywork/`）があり、原稿の書式や視点などの決まりは、それぞれの `AGENTS.md` に書いてある。

## 置き場所

エージェントの道具の正本は `.agents/` に置く。`agents/` が役の手順書、`skills/` がスキル、`rules/` が決まり、`scripts/` が役を頼む仕組み、`packs/` が文体パック、`style/` が使っている文体パックへのリンク。

ツールごとの読み方は次のとおり。共通のものを足すときは、まず `.agents/` に置く。

| ツール | 読むもの |
| --- | --- |
| Claude Code | `.claude/agents`・`.claude/skills`・`.claude/rules` と `CLAUDE.md`。どれも `.agents/` と `AGENTS.md` へのリンク |
| Codex | `AGENTS.md` と `.agents/skills/` を直接読む |
| pi | `AGENTS.md` と `.agents/skills/` を直接読む |
| OpenCode | `AGENTS.md` と `.agents/skills/`。`.opencode/agents` は `.agents/agents` へのリンク。決まりは `opencode.json` の `instructions` に `.agents/rules/*.md` を書く |
| Antigravity（agy） | `GEMINI.md`（`AGENTS.md` へのリンク）と `.agents/` |

- `.agents/rules/` の決まりを自動で読まないツールでは、本文を触る前に自分で読む。
- `.agents/agents/` の手順書をサブエージェントにできないツールでは、その役を担うときの手順書として読む。

## 作業の分担

本文の作業は `.agents/agents/` の役に任せる。メインの会話は、プロットの相談、作者への確認、役への依頼、結果の確認とコミットを受け持つ。

本文を誰が書くかは `.agents/roles.toml` の `[mode] write` で決める（作品ごとに変えるなら、作品のフォルダの `roles.toml`）。

- `ai`（既定）: writer と planner が書き、見る役が直しを返す。下の「一章を書くときの流れ」に従う。
- `human`: 作者が本文を書く。writer と planner は使わず、見る役は本文を書き換えない。下の「添削モードの流れ」に従う。

| 役 | 使う場面 |
| --- | --- |
| `writer` | 章の執筆、加筆、改稿。場面カードや加筆候補を本文にする |
| `planner` | 書く前の場面カード作り。plot と台帳から次の章のカードを起こし、動機の行・運ぶもの・伏線・書かないことまで決めて、穴をカードの段階で塞ぐ。作者に聞くことは、流れを確かめた選択肢つきで出す。本文は書かない |
| `proofreader` | 章ごとの校正。書式・ルビ・口調・視点・文体を最小の修正で直す。添削モードでは直しを赤として積む |
| `checker` | 巻の通し読み。plot・人物・設定・前の巻との整合、日取り、伏線を確かめる。既定は報告だけ |
| `critic` | 敵対的な読者としての批評。つながっていない表現から、理由づけの弱さ、ご都合主義、急に出る要素、そもそもの設定の弱さや矛盾まで、重い順に洗い出す。報告だけ |
| `auditor` | 作者の回答と決定の監査。質問の答えや選択肢の案が、設定と話の流れに照らして無理やりでないか、負債にならないかを判定し、要れば大胆な代案を出す。本文と台帳は直さない |
| `editor` | 担当編集の目で面白さを見る。引き、山場の配分とテンポ、笑い、見せ場、定番の効きを見て、効いている所と伸ばし方を出す。本文と台帳は直さない |
| `reader` | 設定資料を読まない初見読者。本文の束だけを読み、分からない所・引っかかった所・飽きた所を返す |

文体パックが足す役もある（パックの `pack.toml` の `[provides] agents`）。

### 役の頼み方

- 役ごとの担い手は `.agents/roles.toml` に書いてある。一覧は `python3 .agents/scripts/role.py --list --work <作品>`。担い手を変えたいときは、この設定だけを書き換える。
- 担い手が `claude`（既定）の役は、メインの会話から Agent ツールで頼む（`subagent_type` に役の名前）。`roles.toml` にその役の `model` が書いてあれば、Agent ツールの `model` に渡す（既定は書く役と見る役が `sonnet`、proofreader と checker が `haiku`。重くしたい役だけ `opus` に変える）。引き方は `python3 .agents/scripts/role.py <役> --field model`。
- それ以外の担い手の役は `bash .agents/scripts/ask.sh --work <作品> <役> <名前> <依頼のファイル|->` で頼む。名前は作業ごとに一つ（例 `mywork-vol1-04-writer`）。同じ名前で送ると同じ会話に続くので、指示・カード・原稿を読み直させずに済む。会話が長くなって重くなったら、名前を変え、読むものを絞って頼み直す。
- 担い手が使えないとき（利用枠切れなど）は `--fallback` を付けると、`roles.toml` の `fallback` に書いた担い手に回る。
- 書く役と見る役を別のモデルに任せると、同じ癖を見落としにくい。たとえば writer を Gemini にして、critic などを Claude に残す（`roles.toml` の末尾の例）。
- agy は、herdr のペインで対話のまま動かす。`agy -p`（print モード）を他のエージェントから呼ぶと利用規約に触れることがあるので、既定ではどの道具からも呼ばない。規約を確かめたうえで使うときだけ、作者が `roles.toml` の `[agy] allow_print` を `true` にする。エージェントは自分でこの設定を変えない。
- spar（書きながらの壁打ち）と first-read（初見読み）の相手も、同じ設定の `[helpers]` で決める。

### 一章を書くときの流れ（`write = "ai"`）

上の段が終わってから次の段へ進む。各段の結果はメインの会話が読み、作者に出すものを選ぶ。

1. **planner** — カードを【案】で書く。作者に聞くことは、流れを確かめた選択肢つきの問いで出す。
2. **editor（カード）** — カードの段階で面白さを見る（引き、見せ場、笑いの置き場所、型の繰り返し、拍の詰めすぎと厚く書く所の選び方）。直すならここがいちばん安い。
3. **planner（カードの直し）** — editor の指摘のうち問いでないもの（引きの足し、見せ場の置き場所など）をカードに入れる。問いは 4 に回す。
4. **作者と詰める** — planner と editor の問いを作者に出し、答えを `syuki ask` に積んで決着させる。決着した答えは planner がカードに入れる。
5. **auditor** — 答えとカードを監査する。「無理がある」「負債になる」が出たら、作者に聞き直し、planner がカードを直してから、もう一度 auditor に通す。通ったらカードの【案】を外す。
6. **writer** — 場面ごとにスキル `spar` で引っかかりを潰しながら、カードを本文にする（台帳の記録、`syuki check`・`render`、なんで？テストまで）。
7. **first-read の軽い読み**と **critic（章）** — 同時に回す。軽い読みは初見の引っかかり、critic は流れと設定の穴。重い指摘は、二人で重なった所から片づける。文体パックが足す役も同時に回してよい。
   - **editor（本文）** も回すのは、次のどれかに当たる章だけ: 山場か見せ場がある、日常回で笑いや人物の魅力が主な中身、軽い読みで続きを読みたい度が 3 以下か飽きた所が挙がった（その場合は軽い読みのあとに回す）。
8. **直し** — 本文で済むものは writer に戻す。作者の判断が要るものは作者に出し、答えを auditor に通してから writer に渡す。直しのあとは `syuki impact` で後ろの章への影響を見て、大きく変えたなら 7 をもう一度回す。
9. **proofreader** — 中身が固まってから最後に校正する。先に校正すると、直しのたびにやり直しになる。
10. **コミット** — メインの会話が確かめてコミットする。

小さな直し（数行の加筆、言い回しの変更）なら、1〜5 を飛ばして 6 から始め、7 は軽い読みだけでよい。

#### 段（`[mode] flow`）

上の 1〜10 は `full`。どの段で回すかは `roles.toml` の `[mode] flow` で決める（引き方は `python3 .agents/scripts/role.py --setting mode.flow --work <作品>`）。既定は `standard`。

| 段 | `full` | `standard`（既定） | `lite` |
| --- | --- | --- | --- |
| 1〜3 planner・editor（カード） | 全部 | 全部 | 1・2 だけ（editor の指摘は writer に渡す） |
| 5 auditor | 回す | 作者が問いに答えたときだけ | 回さない |
| 6 writer | spar あり | spar あり | spar なし |
| 7 見直し | 軽い読み・critic・パックの見る役・editor（条件つき） | critic を一回 | critic を一回（読むのは章の本文と `syuki brief 章:場面` だけ） |
| 9 proofreader | 回す | 回す | 回さない |
| 初見読み | 章ごとと巻 | 巻のときだけ | 回さない |

- `standard` の 7: critic の依頼文に「文体パックの見る役（`pack.toml` の `[provides] agents`。light-novel 以外では無いこともある）の観点も見る」と書き、見直しを一回にまとめる。
- `lite` で省いた段（パックの見る役、spar、auditor、初見読み、proofreader）は、`syuki lint` と `syuki check` で代える。
- 段にかかわらず、`syuki check` の違反が 0 になり、writer が `syuki lint` の指摘を見終えるまでは、LLM の見る役を回さない。
- 段にかかわらず、見る役は plot 全体や前の章を丸ごと読まない。先に `syuki brief 章:場面` と対象の章を読み、要るときだけ `syuki search` などで広げる。

### 添削モードの流れ（`write = "human"`）

作者が書いた章を、見る役が読んで返す。本文は作者だけが書き換える。`standard` と `lite` では 1 の初見読みを省き、`lite` では 2 の editor と 4 の proofreader も省く。

1. **first-read の軽い読み**、**critic（章）**、文体パックの見る役 — 同時に回す。本文の一か所に結び付く指摘は、報告ファイルとは別に `.agents/scripts/review_add.py` で shosai の指摘ファイル（`review/<巻>.json`）にも積む。
2. **editor（本文）** — 上の 7 と同じ条件の章で回す。
3. **作者が読む** — 作者が shosai で指摘を本文と並べて読み、直すかどうかを決める。筋や設定の問いは `syuki ask` に積む。
4. **proofreader** — 作者の直しが済んでから回す。直しの案は本文に入れず、赤（`before`/`after` を持つ指摘）として積む。作者が shosai で一つずつ採るか決め、「適用」で本文に入る。
5. **コミット** — 作者が決めたあとで、メインの会話が確かめてコミットする。

### 巻が揃ったら

1. **checker** — 巻を通して、plot・台帳・前の巻との整合を確かめる。
2. **first-read の重い読み**、**critic（巻）**、**editor（巻）** — 同時に回す。初見の抜け、穴、面白さを巻の単位で見る。
3. 章の流れの 4〜10（添削モードなら 3〜5）と同じ手順で、作者と詰め、auditor を通し、直して、proofreader で仕上げる。

- 作者に選択肢を出すときも、先に各案を前後の本文と設定に当てて確かめる（迷うときは auditor に案を監査させる）。
- おかしな所を生む、負債になる（あとで説明や言い訳を足し続ける）くらいなら、継ぎ当てより大胆な変更（設定の変更、場面の組み直し、前の決定の取り消し）を優先する。
- 依頼文には、作品、章、参照する plot の節、コミットしてよいかを書く。
- 別の作品のフォルダは、頼まれない限り触らない。

### 引き継ぎ（handoff）

- 本文の場所は、行番号でなく引用文（と章:場面）で書く。校正で行番号がずれるから。
- 「次」には、章割りの順で次に書く章を書く。幕間（例: 04b）も一つの章として数え、飛ばさない。

## 文体パック

ジャンルに固有の書き方と見方は、文体パック（`.agents/packs/<名前>/`）にまとめてある。役の手順書はジャンルを問わない形で書いてあり、パックが次の形で重なる。

- `bash .agents/scripts/link-pack.sh <名前>` でつなぐ。パックのスキル・決まり・役を `.agents/skills/`・`rules/`・`agents/` に、パックそのものを `.agents/style/` にリンクし、`roles.toml` の `[style] pack` を同じ名前にする。
- 役ごとの見方は `.agents/style/roles/<役>.md`。各役は手順書と一緒にこれを読む。
- 書き方と lint のスキルは `.agents/skills/<パック>/`（パックと同じ名前）。lint は `syuki lint <章>` がこのスキルの `scripts/` を使う。
- パックの決まり（`.agents/rules/` にリンクしたもの）は、どの役も本文を触る前に読む。
- 中身と、作品ごとに変えられる所は、パックの `pack.toml` に書いてある。
