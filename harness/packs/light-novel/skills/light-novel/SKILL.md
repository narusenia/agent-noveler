# ライトノベル

## 結論

設計ファイルが正本で、本文はその実装である。ログライン、視点、結末、口調を固定してから、頼まれた範囲だけ書く。文体を盛らない。解説・代替案・次巻は頼まれたときだけ出す。

## 前提

- 対象は日本語の商業ラノベおよび Web 小説。純文学ではない。
- 読み手はスマホ縦読みを想定する。速度と章末の未解決が優先。
- 視点は作品で固定する。既定は一人称、または三人称限定。頭跳ねはしない。
- チャットは正本ではない。企画・キャラ・場面カードは markdown に書く。
- 挿絵は本文外。本文だけで場面が立つこと。
- 文体は作品ごとに選ぶ。リズムの型（緩急・軽快・描写・饒舌）、笑いとシリアスの配分、口癖、作品の決まり文句は作品の `style/profile.toml` に書き、場面カードで上書きできる。既定は緩急、落差型の切り替え、地の文のツッコミ。
- 作品固有のもの（`style/` の profile.toml、keep.md、cliches.txt、会話の見本）は作品フォルダに置き、スキルには入れない。スキルはどの作品にもそのまま配れる。

## スコープ

依頼を次のどれかに分類し、それ以外はしない。

| 種別 | やること | やらないこと |
| --- | --- | --- |
| 構築 | ログライン、結末、キャラ口調、話ビート、場面カード | 本文、世界設定の百科 |
| 執筆 | 指定シーンまたは指定章の本文 | 前後章の先書き、新キャラの追加 |
| 推敲 | 視点漏れ、説明、AI調、口調の検査と最小修正。「直して」と頼まれたら書き換える。レビュー、文体チェック、AI臭さチェックは書き換えずに違反を返す | 筋の勝手な改変、文体の盛り直し |

不足があるときの質問は最大3つ。足りないまま本文を書かない。

詳細は必要なときだけ読む。

- AI 文の癖（根拠つき）: [references/ai-tells.md](references/ai-tells.md)

## 仕様

1. 作品の正本は `plot.md`。先頭にログライン1行、視点、一人称、結末、クライマックスを置く。
2. キャラは役割、欠落、行動原理、一人称、語尾、禁止語、口調サンプル3つ。見た目の長文は書かない。口調サンプルが無いキャラのセリフは書かない。
3. 話の比率目安は起10 / 承40 / 転40 / 結10。硬く守らず、結末から逆算する。
4. シーンは場面カードが埋まってから書く。空のシーンは書かない。
5. 本文の既定は Web 体裁。地の文と会話の切り替わりで空行。会話は行頭「」。閉じ括弧前の句点は付けない（「行く」。「行く。」は不可）。！？…は付ける。引用は『』。
6. 紙の体裁を指定されたときだけ、地の文を一字下げ、会話行は下げない。作品内で混ぜない。
7. 章末は未解決を1つ残す。解決して終わる章は禁止。
8. 出力は本文か指定した設計メモだけ。
9. 作品の `style/keep.md` にある文（作者が残すと決めた文）は、執筆でも推敲でも変えない。

## 手順

1. 依頼を構築 / 執筆 / 推敲に分ける。
2. 構築か執筆で、作品フォルダに `plot.md` か `characters.md` が無いときは、`python3 scripts/init_work.py 作品フォルダ` で雛形（plot.md、characters.md、style/profile.toml）を置く。作品フォルダの指定が無ければ引数を省き、作業ディレクトリに置く。続けて、依頼文から分かる項目だけを埋め、ログライン、視点、結末のうち埋まらないものを質問して止める。この回は本文を書かない。
3. `plot.md` があるときは読む。執筆の依頼でも、ログライン、視点、結末のどれかが空なら構築に戻り、質問して止める。
4. 執筆なら場面カードを埋める。項目は、誰の視点 / 目的 / 入口の圧 / 出口の未解決 / 守る既出事実 / 厚く書く所と薄く流す所。作品フォルダに `syuki.yml` があるときは、場面ごとに `syuki brief 章:場面` を引き、守る既出事実（居場所・知っていること・知らない秘密・持ち物・文書の正本・伏線）をそこから取る（使い方は syuki スキル）。
5. 本文を書く。1シーン＝1目的。
6. 書いた直後に、視点の越境、説明台詞、同一語尾3連続、章末フックを検査する。本文をファイルに書いたときは `uv run scripts/check_style.py` も回し、今回書いた範囲の違反だけを [references/fix.md](references/fix.md) の「直し方」の表で直してから返す。前からあった本文は、「直して」と頼まれない限り触らない。`syuki.yml` がある作品では、場面の表と出来事を台帳に記録し、`syuki check` と `syuki render` を通す。lint は `syuki lint 章` でも回せる。
7. 差分の要約は頼まれたときだけ、3行以内。

レビューを頼まれたときは、どのエージェントでも本文を書き換えず、[references/review.md](references/review.md) の形で違反を箇所つきで返す。本文を直すのは推敲を頼まれたときだけ。

ラノベらしい文体か、AI臭くないかのチェックを頼まれたときは、本文を書き換えず [references/check.md](references/check.md) の手順で返す。`plot.md` が無くても行う。

「チェックして直して」「AI臭さを消して」「文体を直して」のように書き換えまで頼まれたときは、[references/fix.md](references/fix.md) の手順で直す。本文のファイルを上書きし、チャットには直した件数と残した違反だけを返す。

## 制約

優先順。

1. 視点を漂わせない。指定視点以外の内心、見えない自分の顔、未知情報を書かない。
2. 設定を講義しない。ルールは選択を縛る場面でのみ出す。説明台詞を書かない。新しい情報は1場面に1つ、筋に効く出来事は人づてで済ませない（[references/style.md](references/style.md)「説明」）。
3. 文学調にしない。誰でも書ける美文と比喩の連発を避ける。比喩は視点人物が知っている物で言う。情景（光、音、温度、距離、人の配置）と動きの具体は削らない。文を細切れにせず、文の長さに緩急をつける（[references/rhythm.md](references/rhythm.md)）。
4. AI調を出さない。感情ラベル（悲しかった、怒った）で段落を終えない。定型の連発をしない。章末を要約で締めない。ただし感情そのものは抑えない。山場では声と体で外に出す（泣く、怒鳴る、笑う）。
5. 会話を生きた話し言葉にする。短い一言の応酬、全員同じ温度、台詞の意味を念押しする地の文を避ける（[references/style.md](references/style.md) の「会話」「感情」「戦闘」。悪い例と良い例は [references/dialogue-examples.md](references/dialogue-examples.md)）。
6. 口調を混ぜない。話者タグを外しても誰か分かること。ただし口調の型を固く当てすぎない。口癖は一章1〜2回、効く所だけにし、口癖で人物を立てない。山場では型が崩れてよい。口調の指摘は判断として扱い、迷ったら作者に聞く（[references/fix.md](references/fix.md)「判断の指摘」）。
7. 笑いとシリアスは作品の配分に沿わせる。笑いを説明しない。重い出来事の直後と代償そのものは笑いにしない。喧嘩や代償をすぐ和解に丸めない（[references/comedy.md](references/comedy.md)）。
8. `plot.md`、`characters.md`、`style/` 以外の頼まれていないファイル、続編、新キャラ、設定拡張を作らない。既出の固有名詞と事実は上書きしない。矛盾があれば指摘して止める。
9. 冒頭を天気、目覚め、通学路の日常で始めない。

## 受け入れ基準

- ログライン1行で、誰が何を失い何をする話か言える。
- 視点、一人称、結末が `plot.md` の先頭にある。
- 章内で視点が揺れていない。
- 口調サンプルと矛盾するセリフがない。
- キャラごとの台詞を、名前なしでも区別できる（[references/check.md](references/check.md)「盲検」）。
- 感情を説明しすぎず、動作と会話で伝えている。台詞のあとで地の文が意味を言い直していない。
- 比喩、決まり文句、口癖が章の中で繰り返されていない。
- 修正したとき、作者が気に入った部分（keep.md と、直す範囲の外）が残っている。
- 章末に未解決が1つある。
- 指定外の文章、ファイル、設定を足していない。
